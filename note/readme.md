### Layer-by-Layer Breakdown

**API / Routers Layer (`api/routers/`)**

* FastAPI endpoint definitions for RAG system and user interactions
* Request validation using Pydantic schemas (`api/schemas/`)
* Response serialization, error handling, and status codes
* API documentation and examples automatically generated by FastAPI
* Authentication and authorization hooks (other service, apiGateway)

**Services Layer (`services/`)**

* Core business logic for paper retrieval, summarization, and chat handling
* Integration with external APIs (ArXiv, Ollama, LangChain, Langfuse)
* Complex RAG processing workflows: embedding, similarity search, reranking, post-processing
* Caching and performance optimization (`services/cache/`)
* Storage management and logging for MinIO, Qdrant, Redis
* Error handling and retry mechanisms

**Pipeline Layer (`arxiv_rag_pipeline.py`)**

* Main RAG pipeline for embedding, search from qdrant, build prompt, llm

**Storage / Repositories Layer (`db/`, `services/qdrant/`, `services/minio/`)**

* Database abstraction and CRUD operations (`db/crud/`)
* Query optimization, indexing, and transaction management
* Data consistency, integrity, and schema management
* Metrics collection and monitoring (`storage_metrics.py`, `cache/metrics.py`)

**Models & Schemas (`db/postgresql.py`, `api/schemas/`)**

* Database models using SQLAlchemy or ORM
* Pydantic schemas for API request/response validation
* Data transformation and type checking for maintainability
* Structured models for RAG system entities (papers, embeddings, chat history, users)
